# Aozora-stone-reader 初版の実装と検証記録

記録日 2026年10月9日／公開確認 2026年10月10日

初版の20作品を収録し、縦書き・横書きの読書画面、本棚、設定、目次、しおり、読書位置の保存を実装した。本文は合計613,774文字で、短編に加えて『吾輩は猫である』『坊っちゃん』などの長編を含む。ローカルでのビルドと自動テストを完了し、外字修正後のブラウザE2Eは44件すべて成功した。2026年10月10日に [GitHub Pages](https://hhungry2.github.io/Aozora-stone-reader/) へ初回公開し、公開URLでのブラウザ確認も完了した。

[仕様定義案](specification.md) は、当初の要求と受入目標として保持している。現在の実装状況、採用した処理、確認済みの範囲と残る確認は本記録で示す。作品IDと選定版、底本、取り込み時の検査については [作品取り込みと検証の記録](import-report.md) を参照する。

## 実装した読書機能

| 機能 | 初版の動作 |
| --- | --- |
| 本棚と検索 | 20作品を表示し、題名・副題・著者名・読みを検索する。全半角・大小文字・ひらがなとカタカナを検索用に正規化し、題名順・著者順で並べ替える |
| 縦書きと横書き | 両方向ともstone-engine.jsを通して本文を組み、1画面1ページで表示する。読書中に方向を変更できる |

| 外字 | 公式画像URLのJIS面区点から対応を確定できる外字はUnicode文字へ自動変換し、本文フォントで描画する。変換できない外字は原画像を同梱し、説明文と1文字分の領域を確保して描画する |

設定・読書位置・しおりは、このブラウザのlocalStorageへ保存する。保存データを削除する操作は確認を経て、このアプリのキーだけを対象にする。アカウント、アクセス解析、広告は設けていない。

## 組版と作品データ

採用したstone-engine.jsはnpm公開版 `0.2.0` で、依存の版をlockfileで固定した。Stoneで本文の文字配置を決め、アプリ側がルビ・傍点・画像を追加描画する。長いルビは親文字の領域に収まるよう縮小し、ルビの親文字をページ間で分割しない。行間は、ルビと傍点が重なる場合にも隣の本文と干渉しないよう、仕様案の1.6倍を1.9倍へ変更し、1.9・2.2・2.5倍の3段階とした。

長編を一度にSVG化せず、必要な範囲を組版して現在ページだけを表示する。前後移動のためのページキャッシュは上限を設け、読み進めるたびにSVG要素やキャッシュが増え続けない構成にした。フォントの読み込み完了や画面領域の変更でも、保存する位置は本文のアンカーを使用する。

作品は、公式の書誌CSVに記載されたXHTMLのURLから取得した。選定した作品と関係人物の著作権フラグは、すべて「なし」であることを取り込み時に確認している。本文・ルビ・注記・外字画像をUTF-8のJSONへ変換し、原文の出典URL、取得日時、SHA-256、底本・制作情報と変換記録を保持した。

| 外字画像の使用箇所 | 0 |

通常のアプリビルドでは作品を取得し直さない。依存パッケージをインストールした後は、同梱した `public/data/` からネットワーク接続なしでビルドできる。ブラウザは作品を開いた時点で、その作品のJSONを読み込む。

## 外字の自動変換と犍陀多の表示修正

『蜘蛛の糸』の「犍」は原XHTMLで16×16pxの外字画像となっていた。アプリは画像を1文字サイズで描いていたが、画像位置を表すU+FFFCのCanvas計測が0pxとなり、次の「陀」と重なっていた。組版前に画像外字へ1文字分の送りを設定し、この重なりを修正した。

JIS外字全体へ処理を広げ、公式画像URLの面区点と原注記を照合して、Python標準の `euc_jis_2004` でUnicodeへ変換する。面2はJIS X 0213の割当区に限定し、JIS X 0212へのフォールバックで誤った文字を得ることを防ぐ。規格外の区や未定義の対応など、変換を確定できない外字は従来の画像処理へ渡す。画像取得は既存の公式HTTPS制限に従い、非公式の出典からは取得しない。原注記の面区点がURLと異なる場合は取り込みを中止する。

20作品を再生成し、35種類・88箇所すべてをUnicode化した。『蜘蛛の糸』の「犍」17箇所も本文フォントで描画する。変換文字・面区点・コードポイント列・使用コーデック・元画像URL・元注記・根拠URL・変換後のUTF-16範囲をJSONへ記録した。独立抽出した原文との本文・ルビ照合に加え、変換記録を逆にたどって元のU+FFFC本文へ戻ることも検証した。対応表との独立照合では、35種類すべてが [Project X0213の2004対応表](https://x0213.org/codetable/jisx0213-2004-std.txt) と一致した。

ブロックIDを全作品で保持した。7作品の変換はUTF-16長が変わらないため、元の版との位置互換を明示した。『檸檬』の「𤄃」（U+24103）はUTF-16で1単位増えるため、元画像を使った原文版と一致する保存記録だけ、変換位置と文字長の差分から読書位置・しおりを補正する。補助漢字と結合文字列を含む場合も、ルビ・傍点・残る画像の範囲を変換後の文字列に合わせて計算する。

取り込み処理の回帰テスト10件では、BMP・補助漢字・結合列の変換、規格外番号の画像維持、注記不一致の拒否、複数変換後のルビ・傍点・画像範囲、原文指紋への逆変換、誤った位置互換宣言の拒否を確認した。本番ビルドと全20作品のデータ検証も成功した。

外字E2Eを各ブラウザ構成に2件ずつ追加した。『蜘蛛の糸』の旧画像版から読書位置・しおりを復元し、縦横とも「犍陀多」のUnicode本文・同じフォント設定・3文字分の配置・ルビを検証した。画像で残す外字は専用fixtureで確認し、前後の本文の間に1文字分を確保することを実ブラウザの座標で検証した。既存の読書・コピー等36件と追加8件、合計44件が成功した。

## マウスホイールによるページ送り

本文の表示領域にホイール操作を追加した。縦書き・横書きとも下で次ページ、上で前ページへ移動する。本文のページ送りとして処理したホイールイベントは既定スクロールを止め、外側の画面まで一緒に動かさない。

ピクセル・行・ページの各デルタ単位を換算し、微小な入力は40px相当まで累積する。180msを超えて入力が途切れた場合や入力方向が変わった場合は累積をリセットする。ページを送ってから300msは追加の入力を破棄し、慣性入力による移動を予約しない。先頭・末尾や組版中・エラー時は移動しない。

設定・目次・しおり等のダイアログを開いている間は本文のページ送りを抑止し、ダイアログ内の通常スクロールを維持する。修飾キーを伴うホイール操作とフォーム操作はブラウザへ渡す。従来のボタン・キーボード・スワイプも引き続き使える。
