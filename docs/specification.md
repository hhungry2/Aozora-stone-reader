# Aozora-stone-reader 仕様定義案

仕様版 0.1 Draft

作成日 2026年10月9日

Aozora-stone-reader は、青空文庫の文学作品を縦書きと横書きで読める、GitHub Pages 上のブラウザ向けリーダーとする。本文の組版には両表示とも stone-engine.js を使う。初版は選定した20作品程度を対象にし、ルビと本文を欠落なく表示しながら、表示方向や文字サイズを変えても読書位置を保てることを優先する。

この仕様では「縦表示・横表示」を文字の組み方向である縦書き・横書きとして扱う。端末の縦持ち・横持ちにも、それぞれの組み方向で対応する。

## 合意した要件と初版の提案

| 区分 | 内容 |
| --- | --- |
| ユーザー指定 | プロジェクト名は Aozora-stone-reader |
| ユーザー指定 | stone-engine.js を利用する |
| ユーザー指定 | 縦書き・横書きに対応する |
| ユーザー指定 | GitHub Pages 上で青空文庫の作品を読める |
| ユーザー指定 | まず仕様定義を行う |
| 追加確認済み | 初版は選定した20作品程度から開始し、順次追加する |
| 初版の提案 | 作品をビルド前に取得・変換し、サイトと一緒に配信する |
| 初版の提案 | 縦書き・横書きとも1画面1ページのページ送り方式にする |
| 初版の提案 | React、TypeScript、Vite を採用する |
| 初版の提案 | ログインを設けず、設定・読書位置・しおりを利用端末に保存する |

以下の初期値・技術構成・品質目標は実装のための提案とする。アプリ実装と公開は次工程で行う。

## 初版の範囲

初版の利用者は、PC・スマートフォン・タブレットのブラウザで日本文学を読む人とする。画面の操作表示は日本語とし、インストールやアカウント作成を必要としない。

| 機能 | 初版での扱い |
| --- | --- |
| 作品一覧と検索 | 収録した約20作品を作品名・作家名・読みで検索する |
| 作品情報 | 題名、著者・翻訳者、底本、出典、対応状況を表示する |
| 縦書きと横書き | 両方を stone-engine.js で表示し、読書中に切り替える |
| ルビ | 通常の右ルビ／横書きの上ルビを表示する。非表示にもできる |
| 日本語組版 | 禁則処理、約物の詰め、縦中横、段落・改行を扱う |
| 注記 | 対応表に定める見出し、字下げ、傍点、外字等を扱う |
| ページ送り | ボタン、キーボード、スワイプで操作する |
| 目次 | 作品内に明示された見出しへ移動する |
| 読書設定 | 文字サイズ、行間、フォント種別、配色を変更する |
| 読書位置 | 自動保存し、作品を開き直したときに続きから読める |
| しおりと履歴 | 複数のしおりを追加・削除し、最近読んだ作品に戻れる |
| 作品URL | 作品を直接開けるURLを提供する |
| 出典とライセンス | 青空文庫と使用ソフトウェアの情報を表示する |

連続スクロール、見開き、本文内検索、注釈の書き込み、EPUB/PDF対応、任意URLやローカルファイルの取り込み、音声読み上げ機能、PWAによるオフライン保証、端末間同期、全作品検索は将来拡張とする。スクリーンリーダーによる利用は初版の品質要件に含める。

## 画面と利用の流れ

| 画面 | 内容と主な操作 |
| --- | --- |
| 本棚 | 収録作品一覧、検索、並べ替え、最近読んだ作品、「続きから読む」 |
| 作品情報 | 書誌情報、「最初から読む」「続きから読む」、青空文庫の図書カードへのリンク |
| リーダー | 本文、作品名、前へ・次へ、進捗、縦横切替、目次、しおり、設定、本棚に戻る |
| 目次としおり | 見出し・しおりの一覧、該当箇所への移動、しおり削除 |
| 設定 | 表示方向、フォント、文字サイズ、行間、配色、ルビ表示 |
| このアプリについて | 出典、収録方針、第三者ライセンス、端末内の保存データ削除 |

目次・しおり・設定はリーダー内のパネルとして開く。開閉時は読書位置を維持する。パネルを閉じると操作元へフォーカスを戻す。

初回は「本棚 → 作品情報 → 最初から読む」と進む。履歴がある作品では「続きから読む」を提示する。「最初から読む」を選んだ時点で、保存していた読書位置を先頭へ更新する。しおりは残す。

検索は題名・副題・著者名・翻訳者名・それらの読みの部分一致とする。検索用文字列だけを全半角・英字大小・ひらがな／カタカナで正規化し、本文の表記は変えない。題名順・著者順を用意し、同順の場合は作品IDで固定する。検索条件は本棚に戻った際に復元する。

検索結果がないときは条件を解除できる表示にする。存在しない作品IDのURLでは、本棚へ戻れる案内を表示する。

## 本文の表示とページ送り

### 縦書きと横書き

| 項目 | 縦書き | 横書き |
| --- | --- | --- |
| 組み方向 | 上から下、列は右から左 | 左から右、行は上から下 |
| Stone の direction | `tbRl` | `lrTb` |
| ルビの位置 | 親文字の右 | 親文字の上 |
| 初版の表示単位 | 1画面1ページ | 1画面1ページ |
| 次へボタンの配置 | 本文領域の左側 | 本文領域の右側 |
| 前へボタンの配置 | 本文領域の右側 | 本文領域の左側 |
| 左右キー | 左で次へ、右で前へ | 右で次へ、左で前へ |
| スワイプ | 右へスワイプで次へ | 左へスワイプで次へ |

ボタンには矢印と「前へ」「次へ」の名前を付ける。PageDown と Space は両表示で次へ、PageUp と Shift+Space は前へとする。入力欄・設定パネルにフォーカスがあるときはページ送りを起動しない。本文の選択操作中もスワイプによるページ送りを起動しない。

縦横切替は端末の回転と独立させる。表示方向、文字サイズ、行間、フォント、画面サイズが変わった場合は再組版し、変更前の読書位置を含むページを表示する。再組版中に一時的な先頭ページへジャンプさせない。

### ページの境界

ページ境界は文字数の固定値で切らず、実際のフォント・画面領域・ルビの必要領域を含めた組版結果で求める。禁則処理、書記素、縦中横のまとまり、ルビの親文字のまとまりを壊さない。ルビが1行に収まらない場合の扱いは最初の技術検証で確定し、未対応の形式を含む作品は公開対象から外す。

Stone の領域制限による省略記号を、本文の続きを処理する仕組みには使わない。前後のページで本文が重複・欠落しないことを必須とする。親文字をページ間で分断するルビや、ルビの読みだけが別ページへ残る表示は認めない。

先頭・末尾では移動できない方向のボタンを無効にする。末尾には「読み終わり」と本棚へ戻る操作を表示し、付随する底本・制作情報を参照できるようにする。

進捗はルビの読み・メタデータを除く正規化本文中の位置で算出する。ページ番号は現在のレイアウトだけに有効な表示値とする。総ページ数をまだ計算していない場合は「12ページ・進捗35%」などと表示し、不確かな総ページ数を出さない。空本文・計算中・末尾では適切な専用表示にする。

### 初期設定の提案

| 設定 | 初期値 | 選択範囲 |
| --- | --- | --- |
| 表示方向 | 縦書き | 縦書き／横書き |
| フォント | システムの明朝体 | 明朝体／ゴシック体 |
| 文字サイズ | 20px相当 | 16〜36px相当、2px刻み |
| 行送り | 本文文字サイズの1.9倍 | 1.6／1.9／2.2倍 |
| 配色 | 生成り | 白／生成り／暗色 |
| ルビ | 表示 | 表示／非表示 |
| 約物と禁則 | `punctuationMode: stone`、禁則有効 | 初版は固定 |
| 縦中横 | エンジン標準の2桁以下の数字 | 初版は固定 |

ルビや傍点が衝突する行送りは、必要な最小値まで広げる。配色のみの変更ではページ境界を変えない。端末にあるフォントを優先し、初版は大容量の日本語Webフォントを必須にしない。

## 青空文庫データの取得と収録

### 初版の配信方式

初版は、青空文庫公式の書誌CSVと選定作品のXHTMLを、開発側の取り込み処理で取得する。文字コードを判定・変換し、正規化した作品JSONと必要な画像をGitHub Pagesから配信する。ブラウザは同一サイトの作品JSONだけを作品を開くタイミングで取得する。

```text
青空文庫の公式CSVと選定作品XHTML
                ↓ 開発時の取り込みと品質確認
UTF-8の書誌JSON・作品JSON・必要画像
                ↓ サイトと一緒にビルドして配信
GitHub Pages
                ↓ 作品を開いたときに取得
正規化本文 → Stoneによる組版 → ルビ等の追加描画 → 読書画面
```

通常のアプリビルドは、取得済みで版を固定したデータから実行できるようにする。上流サイトの一時的な停止で、既存作品のビルドや公開が止まらない構成にする。

青空文庫公式の作品ファイルをブラウザから直接取得する方式は、初版の前提にしない。2026年10月9日に確認した『羅生門』の作品レスポンスでは `Access-Control-Allow-Origin` がなく、GitHub Pagesからの別オリジン取得を許可する状態を確認できなかった。この観測は全作品・将来の配信設定を保証するものではない。[確認した公式本文](https://www.aozora.gr.jp/cards/000879/files/127_15260.html)

GitHub上のTXTミラーを使う方式は拡張候補とする。確認できた `aozorahack/aozorabunko_text` はCORSを許可する本文を配信しているが、リポジトリへの最終pushは2023年3月22日だったため、公式の最新本文を得る取得元にはしない。独自の中継サーバーは初版では設けない。

### 取り込み処理

1. 公式CSVを読み、作品IDで集約する。著者・翻訳者など人物別の複数行を、別作品として重複登録しない。
2. 収録対象リストで約20作品を選ぶ。著者と翻訳者を含む権利状態を確認する。作品ファイルのURLはCSVに記載されたものを使い、作品IDからファイル名を推測しない。
3. CSVとXHTMLの文字コード宣言を確認し、Shift_JIS等からUTF-8へ変換する。文字化けや置換文字を検出した場合は取り込みを失敗させる。
4. XHTMLの本文・見出し・ルビ・注記・制作情報を取り出し、アプリ内部形式へ変換する。XHTMLをブラウザへそのまま挿入しない。
5. 外字や挿絵の参照先を解析する。必要な画像は出典と対応付けて同梱し、外部URLへの依存を残さない。
6. 未対応構造、本文の欠落、親文字とルビの対応、出典情報を確認する。
7. 取得日時、原データのURLとハッシュ、変換器の版、変換記録を保存し、収録データを更新する。

TXTの独自注記パーサーを最初から全面実装することは必須にせず、公式XHTMLで既に構造化された情報を初版の入力とする。XHTMLに残る注記も検出・記録する。公式の注記一覧を対応分類の基準にする。[青空文庫 注記一覧](https://www.aozora.gr.jp/annotation/)

### 本文と注記の対応表

| 要素 | 初版の表示方針 |
| --- | --- |
| 通常本文、段落、明示改行、空行 | 原文の順序と意味のある空白を保つ |
| 通常ルビ | 親文字と読みを分離して保持し、縦横に応じて配置する |
| 章・節の見出し | 見出しとして表示し、目次に載せる |
| 基本的な字下げ | 先頭やブロックの字下げ量を保持する |
| 傍点 | 縦は右、横は上に配置する。ルビとの重なりは技術検証対象 |
| 縦中横 | エンジンの標準範囲で扱う。数字以外の明示指定は対応判定を行う |
| Unicodeに置換できる外字 | 根拠がある対応表を使い、置換内容を記録する |
| 外字画像 | 文字相当の位置に画像として表示し、説明を付ける |
| 挿絵 | 独立したブロックとして表示し、説明・キャプションを保持する |
| 原注・脚注 | 注の存在を示し、対応する内容を参照できるようにする |
| 底本、入力者、校正者、作成・修正情報 | 本文と分けて作品情報・末尾から参照できるようにする |
| 左ルビ、割り注、複雑な訓点・段組・特殊配置 | 初版の完全再現対象外。含まれる作品は収録判定時に検出する |

未対応要素を黙って削除しない。意味を損なわず注の形で保持できる場合は表示方針を記録し、作品情報に対応状況を表示する。本文や読みに欠落を生む場合、その作品は収録しない。約20作品という目標のために、この条件を緩めない。

### 作品の選定

収録候補は短編中心にし、長編も少なくとも1作品含める。候補例は芥川龍之介『羅生門』『鼻』、太宰治『走れメロス』、宮沢賢治『注文の多い料理店』『銀河鉄道の夜』、夏目漱石『吾輩は猫である』とする。実際の収録リストは、図書カードと本文・注記の確認後に作品ID付きで確定する。

作品数だけでなく、ルビ密度、章立て、英数字、約物、傍点、外字、長文を含む組み合わせで品質を確認する。該当例が収録作品にない機能は、小さな検証用テキストを別途用意する。

## 書誌情報と権利表示

初版で配信するのは、青空文庫の情報に基づいて著作権が消滅していることを確認した作品に限定する。翻訳作品は原著者だけでなく翻訳者の状態も確認する。

作品ごとに題名・著者・翻訳者・底本・入力者・校正者・作成日・修正日・青空文庫由来の情報を保持する。表記の現代化や校訂は初版では行わず、形式変換や外字置換などの履歴を残す。

書誌データは青空文庫のCC BY 4.0表記とリンクを付け、アプリ用の整形・抽出を行った旨を示す。作品本文の扱いとアプリのコードのライセンスは別に管理する。stone-engine.js のMITライセンス表示を保持し、アプリ自身のライセンスは公開前に決定する。[青空文庫収録ファイルの取り扱い規準](https://www.aozora.gr.jp/guide/kijyunn.html)、[stone-engine.js LICENSE](https://github.com/non-standardworld/stone_engine_js/blob/main/LICENSE)

アプリは青空文庫の公式サービスではないことを、出典表示と併せて明示する。

## 内部データと読書位置

### 正規化する作品データ

| データ | 主な項目 |
| --- | --- |
| 書誌 | 作品ID、題名・読み、副題、著者・翻訳者、図書カードURL、権利状態、対応状況 |
| 作品 | スキーマ版、作品ID、内容版、ブロック一覧、本文長、目次、制作情報 |
| 本文ブロック | ブロックID、種別、本文、ルビ・傍点等の範囲、字下げ、原データとの対応 |
| 画像 | アセットID、同梱パス、原URL、説明、ハッシュ |
| 取り込み記録 | 取得日時、原URL・ハッシュ、文字コード、変換器の版、警告・変換記録 |

本文の改行はLFに統一するが、旧字・旧かな・異体字セレクター・結合文字は勝手に正規化しない。ルビの読みは本文文字列に混ぜず、親文字の範囲に結び付ける。

装飾の範囲は正規化本文のUTF-16位置で扱う。分割位置は書記素境界に制限する。元のXHTMLやTXTの位置へ戻す情報が必要な場合は別の対応表にする。

### 永続化する位置

読書位置としおりには、`作品ID + 内容版 + ブロックID + ブロック内UTF-16位置` を保存する。周辺の短い本文も復元用に保持する。画面幅やフォントで変わるページ番号やSVGのrun番号は保存位置に使わない。

ページを送った際は、そのページの先頭本文位置を保存する。目次・しおりから移動した場合は、移動対象位置をアンカーにする。設定変更後は、そのアンカーを含むページに戻す。

同じ内容版なら同じアンカーへ復元する。内容版が変わった場合は周辺本文で照合し、位置を確定できなければ最寄りの見出しまたは先頭に戻し、「作品データの更新により読書位置を調整しました」と表示する。作品の更新でしおりを黙って別の文章へ結び付けない。

## 保存と障害時の動作

初版は小さな読書状態をlocalStorageに保存する。キーにはアプリ固有の接頭辞と保存形式の版を付け、同じGitHub Pagesオリジンにある他アプリのデータと衝突させない。

| 保存対象 | タイミングと扱い |
| --- | --- |
| 表示設定 | 設定変更後に保存する |
| 作品ごとの読書位置 | ページ移動・目次移動・設定変更後に保存する。終了イベントだけに依存しない |
| しおり | 作品・位置・登録日時・本文抜粋を保存する |
| 最近読んだ作品 | 最終閲覧日時を保存し、最近20作品を表示する |

保存不可・容量超過・データ破損時も読書を継続できるようにする。保存できない場合は「この環境では読書位置を保存できません」と伝え、読書中の状態はメモリに保持する。保存データを読み込む際は形式を検証し、不正な一項目でアプリ全体が停止しないようにする。

「端末内の保存データを削除」は確認ダイアログを経て、このアプリのキーだけを削除する。ブラウザや端末を変えると保存状態は共有されず、ブラウザのデータ削除によって消えることを設定画面で説明する。

作品の取得失敗時は再試行と本棚に戻る操作を示す。再組版に失敗した場合は作品・位置・設定を維持し、再試行と青空文庫の原文へのリンクを提示する。初版ではオフラインで読めることを保証しない。

## 技術構成とGitHub Pagesへの配置

| 領域 | 提案 |
| --- | --- |
| UI | ReactとTypeScript |
| 開発とビルド | Viteによる静的ビルド |
| 組版 | `@non-standardworld/stone-engine.js` |
| 描画アダプター | Stoneの低レベル組版APIとSVG描画に、ページ分割・ルビ等を追加 |
| データ取り込み | ビルドと分離した取得・変換コマンド |
| 作品配信 | `data/catalog.json`、作品ごとのJSON、必要な画像 |
| 端末内保存 | localStorage |
| 画面遷移 | ハッシュ形式。例 `#/works/作品ID`、`#/read/作品ID` |
| 公開 | GitHub Actionsで静的ファイルをビルドし、GitHub Pagesへ配置 |

2026年10月9日に確認した公開npm版 `0.2.0` を最初の検証候補とする。公開パッケージで縦横の方向指定、低レベル組版・SVG描画API、ルビ読みの除外、MITライセンスの同梱を確認した。採用版を完全固定し、lockfileを保存する。mainブランチの今後の修正がそのまま公開npm版にあるとは仮定しない。更新時は組版・ルビ・改ページの回帰確認を行う。[公開0.2.0パッケージ](https://registry.npmjs.org/@non-standardworld/stone-engine.js/-/stone-engine.js-0.2.0.tgz)

Stone の公開APIは縦横の方向、文字配置、行番号等を提供する一方、公開0.2.0はHTMLの `rt`・`rp` を本文抽出から除く。青空文庫のルビをそのまま渡す構成は成立しないため、ルビの解析と描画をアプリ側で行う。[公式README](https://github.com/non-standardworld/stone_engine_js#readme)、[公開版と照合した抽出処理](https://github.com/non-standardworld/stone_engine_js/blob/79a07777bcec540d94c5bd5304a68e427a1f49e6/src/render/spans.ts)

ルビ・傍点の領域を確保してStoneで本文を組み、親文字の座標に対応する追加描画を行う方式を検証する。ルビの衝突回避・長い読みの扱い・親文字の分割制御まで含めて成立することを確認する。文字の位置情報だけで解決できない場合は、アダプターの改行制御やエンジンへの最小限の拡張を検討する。

長編全体の文字をSVG要素として一括生成しない。章・段落で区切った範囲を組版し、画面に必要な現在ページと前後ページだけを描画する。フォント計測はブラウザで行い、バックグラウンド計算はUIを長時間止めない単位に分割する。

プロジェクトサイトのサブパス `/<repository>/` を考慮し、JS・CSS・作品JSON・画像をその配下で解決する。Viteのbase設定とリンクを統一する。ハッシュ形式のURLを使い、作品の直リンクを再読み込みしてもPagesの404にならないようにする。

公開するのはビルド済みの静的ファイルと作品データとする。初版の配信総量は100MB以内を目安にし、GitHub Pagesの公開サイト上限1GBを超えないことを公開前に確認する。[GitHub Pagesの利用制限](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)

## 品質とアクセシビリティ

| 項目 | 初版の基準 |
| --- | --- |
| 画面幅 | 320px〜1920pxで操作できる。端末の縦横回転に追従する |
| ブラウザ | 公開時点のChrome・Edge・Firefox・Safari安定版を対象とし、iOS Safari・Android Chromeの実機で確認する |
| タッチ | 主要な操作領域を44px相当以上にする |
| キーボード | 本棚・設定・目次・しおり・ページ送りを操作でき、フォーカスが見える |
| 読み上げ | SVGの視覚表示と別に、ルビ・見出しを含む意味のあるHTMLを提供する。二重読み上げを避ける |
| 色 | 本文とUIの通常文字はコントラスト比4.5:1以上を目標とする |
| 拡大 | ブラウザの200%拡大で主要機能を操作できる |
| 動き | 初版のページ送りに長いアニメーションを必須にしない |
| 安全な描画 | 取り込んだHTML・注記・URLを未検証で実行可能なHTMLへ挿入しない |
| プライバシー | 初版はログイン、アクセス解析、広告を設けない |

Stoneの標準コンポーネントが持つ補助テキストを使う場合も、アプリが追加したルビ・注記と整合するか確認する。独自描画を使う場合はアプリ側で補助HTMLを生成する。現在ページの本文をコピーしたときに、表示していない作品の残りや重複した読みを混入させない。フォントの読み込み完了などによる遅い再組版でも、ユーザー設定の変更時と同様に読書位置を維持する。

### 性能目標の提案

以下は保証済みの実測値ではなく、初回の技術検証で測定条件を固定して調整する目標とする。代表的なAndroid端末のChromeとデスクトップChromeで、端末・OS・ブラウザ・画面サイズを記録する。

| 測定 | 目標 |
| --- | --- |
| 取得済み作品から最初の本文ページを表示 | 2秒以内 |
| 組版済み隣接ページへの移動 | 95%の操作で200ms以内 |
| 縦横切替・文字サイズ変更後の現在位置表示 | 1秒以内 |
| 初回の作品取得 | 進捗または読み込み中の状態が分かり、操作を中断できる |
| 長編の表示 | 全文のSVGを同時に保持せず、ページ送りで描画要素数が増え続けない |

初期表示で全作品本文をダウンロードしない。全文のページ数が未計算でも、先頭や保存位置から読み始められるようにする。

特にA03〜A06は、短編だけでなく長文・ルビ・外字を含む検証用本文で確認する。自動確認はパーサーと本文範囲の完全性、位置復元など壊れやすい処理に集中し、文字配置は実ブラウザの画像と目視で検証する。

## 実装の進め方

1. **組版の技術検証**：固定したStoneの版で、縦横、ルビ、傍点、外字、改ページ、位置対応、Safariの縦組み字形を確認する。本文の完全性と読書位置復元までを小さな試作で成立させる。
2. **作品取り込み**：少数の代表作をXHTMLから変換し、注記の対応表と収録条件を確定する。最終的な約20作品のリストを選ぶ。
3. **読書画面**：ページ送り、設定、目次、しおり、保存・復元、補助HTMLを実装する。
4. **本棚と公開準備**：検索、作品情報、出典、障害表示をそろえ、GitHub Pagesのパスと配信量を確認する。
5. **受入確認と公開**：上記の基準を対象ブラウザで確認し、GitHub Pagesへ公開する。

最初の技術検証でルビ・改ページの成立性に問題があれば、原因と必要な拡張を整理して仕様を更新する。ルビを削除したり、片方の組み方向だけに限定した状態を初版完成とは扱わない。
