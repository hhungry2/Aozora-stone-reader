# Aozora Stone Reader

Aozora Stone Readerは、青空文庫の作品を縦書き・横書きで読めるブラウザ向けリーダーです。React・TypeScript・Viteで構築し、両方向の本文組版に [stone-engine.js](https://github.com/non-standardworld/stone_engine_js) を使っています。Stoneの検証用に、ブラウザ標準のCSSだけで本文を表示する比較モードも備えています。

青空文庫の公式CSVで作品と全関係人物の著作権フラグが「なし」の公開作品を、作品ID単位ですべて検索対象にしています。本文を取得・検証できた作品は縦書き・横書きで読めます。本文がない・提供先が公式サイト外・変換を完了できない作品も一覧に残し、公式図書カードへ案内します。収録数と例外は [取り込み記録](docs/import-report.md) に掲載しています。

- [公開サイトを開く](https://hhungry2.github.io/Aozora-stone-reader/)
- [『蜘蛛の糸』を読む](https://hhungry2.github.io/Aozora-stone-reader/#/read/000092)
- [GitHubリポジトリ](https://github.com/hhungry2/Aozora-stone-reader)

[初版の実装と検証記録](docs/implementation-notes.md) に、仕様との対応、自動確認した範囲、実機・読み上げなど残る確認を掲載しています。

## 読書機能

- 読書設定の「表示エンジン」で、従来の「Stone（stone-engine.js）」と比較用の「CSS（ライブラリ未使用）」を切り替えられます。CSSモードはブラウザ標準の`writing-mode: vertical-rl` / `horizontal-tb`とHTMLのルビで本文を表示し、Stoneの組版・SVG描画・コピー処理を使いません。選択したモードは保存し、CSSモードで再訪した場合はStone本体も読み込みません。
- 本棚の検索欄で、題名・副題・著者名・読みから作品を探せます。ひらがな・カタカナ・半角カナ、全角・半角、英字の大文字・小文字を区別しません。「夏目 漱石」「なつめそうせき」など姓名の空白の有無にも対応し、空白で区切った複数語をすべて含む作品に絞れます。
- トップの本棚は「おすすめ順」で、『こころ』『人間失格』『羅生門』『銀河鉄道の夜』など40の名作を先頭に並べます。作品IDで版を固定し、残りの全作品も続けて表示します。作品名順・作家名順にも切り替えられます。
- タイトル全体を囲む（…）・〈…〉・「…」などの括弧は、本棚・読書画面・作品情報で外して表示します。作品名順も括弧を外した読みで並べます。元の書誌データを保持するため、括弧付きの元タイトルでも検索できます。本文と読書位置の識別子は変更しません。
- 本棚の作品名は20〜22px、作家名と主な説明は16〜18px、補足情報は14pxを基本とし、スマートフォンでも読みやすい文字サイズで表示します。
- 表紙の作者名は左下に配置します。読書画面の下部は設定が左、目次が右で、章の見出しがない作品には目次ボタンを表示しません。縦書き・横書きの切り替えは上部にまとめています。
- 表紙の縦書きタイトルに含まれる1〜2桁の数字は、縦中横で横並び・正立に表示します。
- しおりの一覧は保存済みのしおりがあるときだけ開けます。最後のしおりを削除すると一覧を閉じ、空の案内画面は表示しません。
- 著者・翻訳者などの人物の選択、短編・長編、最近読んだ本の絞り込みを検索と組み合わせられます。検索対象は全作品で、本棚は40作品ずつ表示します。前後のページとページ番号で移動でき、検索条件を変えると先頭に戻ります。結果件数を表示し、「検索条件をクリア」ですべての作品に戻れます。題名順・著者順で並べ替え、著者順では同じ作家の作品を題名順にまとめます。
- 縦書き・横書きを切り替え、1画面1ページで読めます。ボタン、キーボード、スワイプ、マウスホイールでページを送れます。本文上で下へスクロールすると次ページ、上へスクロールすると前ページへ移動します。
- 最初のページには、本文の前に題名・副題（ある場合）・著者名を表示します。作品情報も縦書き・横書きの設定に合わせて組版し、見開きでは先頭のページに表示します。
- ルビ、傍点、外字、見出し・字下げを表示し、目次から見出しへ移動できます。JIS面区点で対応を確定できる外字画像は自動的にUnicode文字へ変換し、本文のフォントで表示します。未対応の外字は説明付きの画像として表示します。
- [Stoneプレイグラウンド](https://non-standardworld.github.io/stone_engine_js/)と同じ組版設定を提供します。文字方向、約物（stone・常に全角・常に半角）、文字寄せ（行頭・中央・行末・均等）、行の寄せ（start・middle・end）、フォントサイズ10〜48px、行送り1.00〜3.00倍、和文・欧文別フォント、欧文スケール0.60〜1.20倍、禁則処理、単語での改行、縦中横、文字枠の表示を変更できます。白・生成り・暗色とルビの表示も設定できます。
- 読書位置、しおり、表示設定をブラウザ内に保存し、続きから読めます。表示方向や文字サイズを変えたときも、本文内の位置を使って読み直すページを決めます。
- 読書画面の上段に配色切り替えと「しおり」を配置し、しおりの隣の矢印から保存済みの一覧を開けます。下段は目次・文字サイズ・行送り・ページ送り・設定を横一列に配置し、狭い画面でも1段に収めます。幅480px以下では文字サイズ・行送りのボタンをラベルだけの表示にし、現在値は調整パネルで確認できます。配色は白→生成り→暗色の順に切り替わり、文字サイズと行送りは上向きに開くスライダーと「＋／−」で調整できます。調整パネルを開いても本文の表示領域は変わりません。外側をクリックするかEscキーで閉じられます。
- 設定の「ページの準備」で、従来の「必要なページだけ」、現在位置から先を補充する「10ページ先読み」、作品全体を用意する「全ページ組版」を選べます。先読み中も読書でき、準備状況は本文の下に表示します。組版結果は作品を開いている間だけ保持し、文字設定や本文領域のサイズが変わると作り直します。全ページ組版は長編ほど時間とメモリを使います。
- 本棚の表紙・題名から直接本文を開きます。読書画面のヘッダーにある作品情報ボタン（ⓘ）を開くと、読書時間・文字数、底本・入力者・校正者・出典と、表示形式の変更内容を確認できます。「最初から読む」も同じ画面で選べます。以前の `#/works/作品ID` のリンクは、同じ作品の `#/read/作品ID` に移動します。

## StoneとCSSの表示比較

読書画面の「設定」→「表示エンジン」で切り替えます。初期値はStoneです。比較には同じ作品データを使い、本文中の読書位置としおりを両モードで共有します。ブラウザによる行の分割が異なるため、切り替え後のページ境界やページの先頭は同一とは限りません。

| 項目 | Stone | CSS（ライブラリ未使用） |
| --- | --- | --- |
| 本文の配置 | stone-engine.jsによる組版とSVG描画 | ブラウザ標準のHTMLと`writing-mode` |
| 縦書き・横書き | 両方に対応 | `vertical-rl` / `horizontal-tb` |
| ルビ・傍点・外字・図版 | アプリ側の配置・描画 | HTMLの`ruby`・`rt`、CSSの傍点、画像 |
| ページ送り | 本文範囲をページ単位で組版 | 連続配置された本文を1行分重ねて画面単位で移動 |
| 本文の選択・コピー | Stoneの文字位置から原文を取得 | ブラウザ標準の選択・コピー |
| 目次・しおり・保存位置 | 本文のアンカーを使用 | 同じアンカーをDOMの文字位置へ対応させる |
| 見開き・先読み・約物の幅・行の寄せ・文字枠 | 対応 | 適用せず、専用の設定を無効化 |

CSSモードでも文字サイズ・行送り・フォント・配色・ルビ表示などを変更できます。組版結果はブラウザとフォントに依存します。比較用に本文全体をHTMLとして配置するため、長い作品ではStoneの必要範囲だけを組む方式よりDOMとブラウザの配置処理が増えます。

## ローカルで起動

Node.js 24を使用します。初回に依存パッケージをインストールし、開発サーバーを起動してください。

```sh
npm install
npm run dev
```

表示されたローカルURLをブラウザで開きます。作品データはリポジトリの `public/data/` に入っているため、初回起動のために青空文庫から作品を取得する必要はありません。

本番用の静的ファイルを生成して確認する場合は、次を実行します。

```sh
npm run build
npm run preview
```

成果物は `dist/` に生成します。依存パッケージのインストール後は、通常のビルドにネットワーク接続は不要です。第三者ライセンスの一覧 `public/licenses.txt` は、ビルド前に依存パッケージの許諾文から生成します。

## テスト

```sh
npm test
npx playwright install
npm run test:e2e
```

`npm test` は組版・ページ分割・読書位置・保存処理などの単体テスト、`npm run test:e2e` はブラウザでの読書操作を確認します。Playwright用ブラウザのインストールには初回だけネットワーク接続が必要です。E2Eではデスクトップとモバイル相当の画面を、Chromium・Firefox・WebKitで確認します。

読書画面の応答時間は、本番ビルドを `npm run preview -- --port 4176` で起動してから、別のターミナルで `npm run measure` を実行すると測れます。取得済みの『吾輩は猫である』を開く操作、ページ送り、縦横切替を測定し、条件と結果を `.cache/performance.json` に保存します。外部通信や実機での性能を保証する試験ではありません。

## 全作品の収録と更新

公式の公開作品CSVを作品IDでまとめ、作品と著者・翻訳者など**全関係人物**の著作権フラグが明示的に「なし」の作品だけを対象にします。異なる版・表記の作品IDは統合せず、副題と文字遣い種別を本棚に表示します。作業中の作品や著作権が存続する作品は含めません。

本文は作品を開いたときだけ取得します。新規収録の本文と配信用カタログはgzip形式で保存し、ブラウザで展開します。元の40作品の本文は従来のJSON形式です。メモリ上の本文キャッシュは3作品までに制限し、検索用の正規化情報・並び順は一覧を読み込んだときに準備します。書誌データの元JSONもリポジトリに保持します。

Python 3.12以降で実行できます。通常のWebビルドは取り込みを実行せず、同梱データを使用します。

```sh
python -m pip install -r scripts/requirements.txt
python scripts/import_books.py --all
```

成功した作品は `.cache/aozora/converted/` に保存します。再実行では、CSV行・変換器・出力ハッシュが一致する成功済みの作品を再利用し、失敗した作品を再試行します。原HTML、書誌CSV、原画像、URL・取得日時・SHA-256は `.cache/aozora/` に保存します。最大8プロセス、各プロセスで毎秒1リクエストを上限とし、通信エラーは待ち時間を増やして再試行します。

```sh
python scripts/import_books.py --all --workers 8
python scripts/import_books.py --all --offline
python scripts/import_books.py --all --limit 100
python scripts/import_books.py --validate-only
python -m unittest discover -s scripts -p 'test_*.py'
```

`--limit` は診断用で、公開用カタログを更新しません。公式データを取り直す場合は `--all --refresh` を使用します。フラグなしの実行も全作品を対象にします。以前の40作品だけを再生成する場合は、明示的に `--curated` を指定します。

本文・ルビの親文字と読み・UTF-16範囲・外字・画像の同梱・目次リンク・出典情報を検証してから公開用データに反映します。JIS X 0213:2004の面区点が確定できる外字画像はUnicode化し、文字・元画像・注記・位置を記録します。ルビの読みの中の外字にも対応します。大きな挿絵・図版は専用ページで表示し、小さな外字画像は本文中に配置します。旧HTMLの本文と出典、旧文字コード名、Windows拡張文字を扱い、旧形式の括弧付きルビや簡略化した配置は作品情報で説明します。原文に親文字のないルビや入れ子のルビがある場合は、表示できない読みを作品情報と変換記録に保持します。

取り込み結果は以下に保存します。

- `public/data/catalog.json` / `catalog.json.gz`: 著作権切れ全作品の検索一覧と本文の有無。
- `public/data/import-manifest.json`: 公式CSVの指紋、対象ID、作品ごとの権利フラグ・本文と注釈の監査結果。
- `public/data/import-status.json`: 対象数・本文収録数・容量と、本文を同梱できない作品の理由。
- [取り込み記録](docs/import-report.md): 人が読める集計と例外一覧。

公開ワークフローでも全作品のデータ検証とPythonの回帰テストを行います。組版テストは元の40作品の全ページと、追加作品から選んだ24作品の先頭・中間・末尾を両方向で確認します。

## GitHub Pagesへ公開

[公開ワークフロー](.github/workflows/pages.yml) は、`main` へのpushまたは `main` 上での手動実行で依存パッケージをインストールし、単体テストとビルドを実行して `dist/` をGitHub Pagesへ配信します。公開リポジトリ `hhungry2/Aozora-stone-reader` は **GitHub Actions** を配信元に設定済みで、`main` へのpushが公開サイトへ自動反映されます。別のリポジトリで使用する場合は、**Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選んでください。

Pagesのサブパスはワークフローが `VITE_BASE_PATH` へ渡します。画面のURLはハッシュ形式のため、作品への直接リンクを開いてもGitHub Pages側のルート設定は不要です。別の静的ホストでサブパスを指定する場合も、ビルド時に `VITE_BASE_PATH` を設定できます。

## 初版の制約

- 長いルビは親文字の領域に収まるよう縮小します。複雑な熟語ルビの割り付けには改善の余地があります。
- 地付き・字詰め・囲み・添字の配置は簡略化しています。文字と校訂注記は保持し、作品情報に変更内容を示します。連続空行は段落境界へ統合します。
- 設定・読書位置・しおりは端末内のブラウザに保存します。端末間同期はなく、ブラウザの保存データ削除で消えます。
- PWAとオフライン読書の保証、本文内検索、任意作品URLの取り込みは初版に含めていません。
- Noto Sans JP・Noto Serif JP・Zen Kaku Gothic New・Shippori Minchoは、選択時にGoogle Fontsから読み込みます。端末の明朝体・ゴシック体とヒラギノも選べます。通信できない場合や端末に書体がない場合は代替フォントで表示するため、端末によって字形は異なります。
- 狭い行送りはルビや傍点が隣の行へ近づくため、読みづらいときは行送りを広げてください。
